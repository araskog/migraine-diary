# Domain Glossary

Use these product terms consistently in specifications, UI text, code, and tests.

| Term | Meaning |
|---|---|
| User | A person with an application account and access to their own diary. |
| Diary date | The calendar date to which a diary entry belongs. |
| Migraine day | A date on which the user reports experiencing migraine. It is not an automated diagnosis. |
| Diary entry | A saved record belonging to one user and one diary date. |
| Missing entry | No entry exists for the user/date. This does not establish that they were migraine-free. |
| Migraine-free day | A day explicitly reported as migraine-free; never inferred from a missing entry. |
| Recorded day | A diary date with a saved migraine or migraine-free status. Optional detail fields belong only to recorded days. |
| Symptom (recorded) | A selected item from the app’s fixed symptom catalog on a migraine day. A checklist of experience, not a diagnosis. |
| Menstruation tracking | An optional account preference that enables cycle-related fields on diary dates. When off, those fields are not shown. |
| Personal note | Optional free-text the user attaches to a recorded day. It is health-related when it describes symptoms or care. |
| Wellness details | Optional sleep, stress, and related fields on a recorded day. They do not by themselves establish migraine status. |
| Daily life impact (recorded) | Selected items from a fixed list describing how migraine affected activities (for example missed work). Migraine days only. |

Do not use “migraine attack” interchangeably with “migraine day”: counting dates does not establish the number of attacks.
